# AXON 1.2.0

## Cambios

- **Backups:** asistente de cuatro pasos para carpetas, archivos de un disco, configuración de AXON y PostgreSQL. Hasta cinco destinos físicos independientes, frecuencia cada N días, versiones, cola persistente, espera de discos desconectados y recuperación selectiva conservando originales. Copias cifradas y clave de recuperación descargable.
- **Conexiones:** configuración de Dropbox, Google Drive y OneDrive; navegación de archivos y biblioteca, selección de cuentas visibles y transferencias con comprobación. Cada proveedor requiere su aplicación OAuth y autorización; instalar AXON no conecta una cuenta.
- **Agentes:** permisos por token, descubrimiento de capacidades REST/MCP, límites por tipo de operación y transferencias de nube mediante el cliente distribuido. Credenciales privadas y revocables.
- **Software:** inventario nativo, planes de instalación/actualización, comprobación del resultado e iconos con catálogo persistente y elección manual.
- **Interfaz:** login renovado, navegación y controles adaptables, assets con huella de contenido, HTML/API privados sin caché y correcciones de escritorio y papelera. Las ediciones simultáneas se serializan en el directorio para evitar un error después de publicar un archivo; el segundo guardado recibe un conflicto sin sobrescribirlo.
- **Instalación:** el contenedor administrado publica su propio nombre para resolver los backups de configuración. La primera actualización desde 1.1 también identifica su propio contenedor y corrige el origen de la política automática de configuración conservando ajustes y versiones anteriores. El montaje del host permite ver discos que se montan después de iniciar AXON. La imagen usa Bun 1.4.2, la misma versión validada en CI.

## Instalar o actualizar

Instalación nueva en Linux con Docker Engine, Compose 2.20+, Git y Python 3.10+:

```bash
curl -fsSL https://raw.githubusercontent.com/LucasSabena/axon/v1.2.0/install.sh -o /tmp/axon-install.sh
bash /tmp/axon-install.sh --ref v1.2.0
```

Instalaciones administradas existentes:

```bash
axon update --ref v1.2.0 --wait
axon status
```

El actualizador construye antes de detener AXON, respalda sus datos y comprueba la revisión nueva. Conserva login, configuración y cuentas; los demás servicios siguen funcionando. Ante un arranque fallido intenta recuperar el código anterior. `axon rollback --wait` vuelve al código anterior manteniendo los datos actuales.

Instalaciones Compose: conservá `.env` y `data/`, obtené esta publicación y reconstruí únicamente AXON. No montes `public/` por separado. La migración al instalador es explícita mediante `--existing-data`; consultá la [guía de instalación](../installation.md).

## Requisitos y alcance

Restic debe estar instalado en el host para ejecutar backups. Los discos de destino deben estar montados; no se formatean ni se inicia un backup de archivos personales al instalar. Los horarios usan Argentina. La copia de un disco contiene archivos, no una imagen arrancable. Guardá la clave de recuperación fuera del servidor. [Guía de Backups](../backups-2026-10-06/README.md).

Esta publicación conserva las políticas y los recibos anteriores. Las copias en el mismo disco del servidor no protegen frente a su pérdida: elegí otro disco desde los ajustes. Las versiones anteriores siguen disponibles hasta aplicar una conservación configurada después de una copia nueva comprobada.
